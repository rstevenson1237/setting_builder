# Dangerous - Key

## Provides
When a DANGEROUS location holds an object whose real function is opening something
somewhere else. What earns a row is `patterns/setting/Keys.md`'s.

## Spec

```
KEY - supply, a key lying here
  1     The object, and what it physically is           (genre: key-forms)
  1     How it is held here                             (genre: key-held)
  1     Why it is down here rather than with its lock
                                                (genre: key-provenance-underground)
  1     A stub row in setting/Keys.md naming this location and the location it
        opens - the second is the obligation
  40%   A clue connecting object to lock, where the connection is not obvious
                                                        (genre: key-clues)
  20%   Evidence it has been used before

KEY - demand, a lock an obligation named here
  1     The lock, and what it physically is
  1     The feature it sits on, matching the setting/Keys.md row that named it
  20%   Evidence it has been forced at, and held
```

**The supply end does not name its lock.** It records a row and stops; the row's `Unlocks`
line is written at 4d, per `templates/Keys.md`. A stub carries a name, a weight and two
tags and no features, so naming a feature at 4c names something that does not exist yet.

**What the row creates instead is an obligation**, which the far location's weight file
draws at rate `1`. An obligation may name a location not yet generated; it may never name
one already written, because there is no longer a draw to honour it. Nothing is owed at the
close of 4c.

## Constraints

- **A key is drawn from two places at two rates, and that is not a duplication.** The
  object found here is treasure, drawn by `dangerous/Treasure.md`; the lock here that
  something elsewhere opens is registry, drawn by the weight file. One location very rarely
  holds both - and where it does, they are two different keys.
