# Steps

A record of the steps taken to build this setting. Each step names what it creates and the
template (and pattern file) it follows - the template's own Context section owns the file
list to read, so a step restates it only where the step itself adds something the template
can't know: build order, phase gating, or stub/registry bookkeeping. Pattern guidance lives
in `patterns/`, in five folders - `setting/`, `region/`, `safe/`, `wild/`, `dangerous/` - and
a step reads only the folder that matches what it is building.

**An id may be retired; an id may never be reassigned.** Retiring one and moving its
citations is a mechanical change - `templates/` cite step ids for their own two-phase
instructions, `tools/validate_setting.py` resolves those against this file, and a missed
one is an error on the next run. Reassigning a freed id to different work is the change no
check can see: every stale citation still resolves, and now points at the wrong step. Where
a rename frees an id, retire it and refill it in separate commits, so nothing cites it in
between.

1. Establish framework
   - 1a. Customize `GENRE.md`, following `templates/Genre.md` and the seed-and-narrow flow in `patterns/setting/Genre.md`: from a pool of 20-30 discrete, specific genre references (authors, single books or series, and TTRPG lines), three rounds of narrowing questions take the user's general request down to one chosen reference; Q2 answers a set of binary/dial axis questions (lethality, population density, magic level, and others as the reference calls for), defaulted to what the reference implies and dialed elsewhere only where the user wants to diverge. The genre-identity paragraph states the chosen reference both specifically and as the general tropes it fulfills. The three tests under **What a line has to earn** are fixed across every genre and reproduced verbatim, never reauthored.
   - 1b. Generate `setting/Tags.md` (~25 flat, genre-derived thematic tags, each with a one-line gloss), following `templates/Tags.md` and `patterns/setting/Tags.md`. Also compiles this build's genre-specific examples into the `## Design patterns` section of every pattern file that carries one, and only those files. Which files those are follows from what a file's output *is*, per `patterns/SPEC.md`: a file that fills a location's body - its Dressing, its Kind, an ingredient drawn into it, a hook hanging off it - is where flat output would show, so that is where specific content is spent. Nothing else is compiled, because nothing else carries the section - the setting-level and region-level files and every classifier hold neutral, permanent content in their Spec instead. A naming procedure is a shape applied to a location rather than content filling one, which is why `patterns/setting/Naming.md` sits at setting level and carries no compiled section. Two draws want more than the plain example swap: demeanor examples go into the two Creature files, and personality examples into `safe/People.md` and `wild/Creature.md`'s own People pattern. Replaces `GENRE.md`'s old Safe/Wild/Dangerous/People/Creatures tag bank outright. **Compile list**, checked against the tree by `tools/validate_setting.py`: `safe/Dressing.md`, `safe/Commerce.md`, `safe/Authority.md`, `safe/Social.md`, `safe/Wealth.md`, `safe/People.md`, `safe/Situation.md`, `safe/Lore.md`, `safe/Key.md`, `safe/Quest.md`, `safe/Faction.md`; `wild/Dressing.md`, `wild/Ruin.md`, `wild/Lair.md`, `wild/NaturalFeature.md`, `wild/Crossing.md`, `wild/Creature.md`, `wild/Hazard.md`, `wild/Mystery.md`, `wild/Treasure.md`, `wild/Quest.md`, `wild/Faction.md`, `wild/Lore.md`, `wild/Key.md`; `dangerous/Dressing.md`, `dangerous/Door.md`, `dangerous/Creature.md`, `dangerous/Faction.md`, `dangerous/Trap.md`, `dangerous/Environmental.md`, `dangerous/Residual.md`, `dangerous/Mystery.md`, `dangerous/Treasure.md`, `dangerous/Quest.md`, `dangerous/Lore.md`, `dangerous/Key.md`.
   - 1c. Seed `setting/Procedures.md` with working default mechanics - tests and consequences, forced damage and hazard tiers, wounds and madness, conditions, searching, time by rating, the three Action Dice scales, and the Difficulty roll - following `templates/Procedures.md` and `patterns/setting/Procedures.md`. Generic by design; tailored at 2h.
   - 1d. Seed `setting/Language.md` with three tongues - a common tongue, an older tongue for ruins and the dead, and one non-human tongue - each with phoneme inventories, a syllable shape, affixes, and a starter root list, following `templates/Language.md` and `patterns/setting/Language.md`. Seeding here rather than later is what makes names generative from 2b onward rather than systematized after the fact.
2. Build the setting
   - 2a. Create `setting/Setting.md` (name, a tag-line pointing to `setting/Tags.md`, referee outline), following `templates/Setting.md` and `patterns/setting/Setting.md`.
   - 2b. Create `setting/History.md` (major events, oldest to newest, each leaving something findable), following `templates/History.md` and `patterns/setting/History.md`.
   - 2c. Create `setting/Truths.md` (rules, classes, or ideas unique to this setting), following `templates/Truths.md` and `patterns/setting/Truths.md`.
   - 2d. Create `setting/Rumours.md` (a d20 table of leads, marked T/P/F), following `templates/Rumours.md` and `patterns/setting/Rumours.md`.
   - 2e. Create `setting/Bestiary.md` (reusable creature templates, each with Description, Range, Sign and Disposition), following `templates/Bestiary.md` and `patterns/setting/Bestiary.md`.
   - 2f. Create `setting/Factions.md` (3 factions, each with a visual identity), following `templates/Factions.md` and `patterns/setting/Factions.md`.
   - 2g. Create `setting/Treasure1.md` through `setting/Treasure5.md` (Treasure Tables I-V), following `templates/Treasure.md` and `patterns/setting/Treasure.md`.
   - 2h. Tailor `setting/Procedures.md` and `setting/Language.md` to this setting, following `templates/Procedures.md` and `templates/Language.md`, and create `setting/Lore.md`, `setting/Keys.md`, `setting/Quests.md`, `setting/NamedCreatures.md`, and `setting/UniqueTreasures.md` as empty stub tables, following `templates/Lore.md`, `templates/Keys.md`, `templates/Quests.md`, `templates/NamedCreatures.md`, and `templates/UniqueTreasures.md`. These five fill in two phases: a stub row (name and location) during 4c, and the full entry at 4d.
3. Build the region
   - 3a. Create `setting/region/Regions.md` (a Regional Gazetteer: region count, rating mix, a die per region), following `templates/Region_Gazetteer.md`. Fixed here rather than earlier, since nothing before this step needed it. Each entry's tags are a forward reference (`Tags: see setting/region/[Code]/Tags.md`) - the file itself doesn't exist until 3c.
   - 3b. Create `setting/region/Connections.mmd` (a mermaid graph of region-to-region connections, existence only), following `templates/Connections.mmd`.
   - 3c. For each region, create its folder (`setting/region/[Code]/`, moved up from 4a since this step now needs it), its own `Tags.md` (~25 tags, same shape as the setting-level pool, following `templates/Tags.md` and `patterns/setting/Tags.md`), and its full `setting/region/[Code].md` Region Overview including its d6 table, following `templates/Region.md` and the matching `patterns/region/Safe.md`, `Wild.md`, or `Dangerous.md`. Fields differ materially by rating - a SAFE overview carries the People roster and the current Situation, a WILD overview the Terrain and Foraging texture narrated between points, a DANGEROUS overview the Architecture and the Danger countdown.
4. Build locations
   - 4a. Add a `Locations.md` gazetteer into each region's folder (created at 3c), taking counts and class mix from its `patterns/region/` file, following `templates/Location_Gazetteer.md`. Stubs carry only a name, weight or classification, and exactly two tags - one pulled from `setting/Tags.md`, one from this region's own `Tags.md`, never freely invented. **Every location in the setting exists as a stub after this step**, which is what lets a Quest or Key name a real target at 4c.
   - 4b. Create each region's connection diagrams, following the topology in its `patterns/region/` file - a shallow hub for SAFE, a forest of trees for WILD, a dense graph for DANGEROUS. SAFE and WILD get one typed location diagram per region, `setting/region/[Code]/Connections.mmd`, following `templates/Region_Connections.mmd`. DANGEROUS gets that file as a **block-to-block diagram asserting existence only**, plus one typed `[Block Name].mmd` per block, following `templates/Block_Connections.mmd`. Locations connect only to locations, and only the location tier carries connection type. A cross-block edge is declared in both block files and must match in existence, type and direction; blocks already written are read for edges declared into a block before that block's diagram is drawn.
   - 4c. For each rating (SAFE, WILD, DANGEROUS) a region contains, for each class within it - WILD: Landmark, then Hidden, then Secret; SAFE has one pass - read that class's own pattern file and generate one `[Location Code].md` per location of that class, following `templates/Location.md`. **In a DANGEROUS region the unit of generation is the block**, one functional quarter per `patterns/region/Dangerous.md`: generate HIGH region-wide first, so every lower tier can foreshadow what is already decided, then block by block, MEDIUM before LOW within each. Generating a block as one batch is what lets a location be written against the others in its quarter rather than alone - `dangerous/Dressing.md`'s bar on reusing a purpose is checkable only at that scale, and both ends of a connection inside one block are written together. The class file's own Spec states which other pattern file(s) each line draws from; no separate file list is needed here. Record every coined proper noun back into `setting/Language.md`. Whenever a Feature calls for Lore, a Key, a Quest, a Named Creature, or a Unique Treasure, add a stub row to the matching `setting/` file.
   - 4d. Once every region has completed 4a-4c, write the full entry for each stub row in `setting/Lore.md`, `Keys.md`, `Quests.md`, `NamedCreatures.md`, and `UniqueTreasures.md`, following `templates/Lore.md`, `templates/Keys.md`, `templates/Quests.md`, `templates/NamedCreatures.md`, and `templates/UniqueTreasures.md`, each of which names its own `patterns/setting/` file. Also grow `setting/Language.md` with any coinage not yet recorded, and revisit `setting/Procedures.md` only if generation turned out to need a mechanic its seed did not cover.
5. Judgement checks
   - 5a. Create/update `checks/TemplateJudgementCheck.md`, following `templates/Template_Judgement_Check.md`.
   - 5b. Create/update `checks/PatternJudgementCheck.md`, following `templates/Pattern_Judgement_Check.md`. Note that the duplication check is **inverted** for `patterns/` - restatement across rating folders is deliberate, so two versions that read the same are a finding.
   - 5c. Once a region's locations are complete, create/update `checks/SettingJudgementCheck.md`, following `templates/Setting_Judgement_Check.md`. Unlike other steps this one reads broadly across levels, since cross-level coherence is what is being judged. This is also where the setting's claims against itself get settled - the only check that reads *upward*: `Truths.md`'s Handles, `History.md`'s Left lines and `Rumours.md`'s Settled-at column get filled with real Location Codes wherever one exists; each Region Overview's claims against its own rooms (a treasure table it says it leans on, a creature it places somewhere, a motif it says repeats) get checked against what the locations actually deliver; `Language.md` gets any coinage not yet recorded. A claim with nothing under it yet is **not** deleted - name it under Room to Grow instead, since a claim already earns its keep at the level that stated it and just hasn't been reached below yet.
