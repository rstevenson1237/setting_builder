---
description: Execute one of the twelve steps, dispatching Builder and Decorator subagents
argument-hint: <n> [--region R0n] [--pass HIGH|MEDIUM|LOW]
---

Run step `$ARGUMENTS` of SPEC.md section 11.1.

**A step may not start until the previous step passes validation.** Check that
first: `python tools/validate.py`. If the run reports errors, stop and say so.

## 1. Ask the question batch. Write nothing yet.

Every step opens with a question batch and generates nothing until it is
answered. This is what stops a large generation being thrown away and rewritten.

Build the batch from the `## Design questions` of every pattern the step will
run — read them out of `DESIGN_PATTERNS.md` and the pattern files themselves —
plus any root-vocabulary proposals for `T-LNG`. A name that needs a root the
registry does not hold is proposed here and written into `T-LNG` before it is
used, never coined in passing (M18).

Ask the batch whole, with genuine alternatives rather than only the conservative
option. Wait for the answers. **Never invent an answer to an open item:** an
invented answer becomes canon silently and no check will catch it.

## 2. Read the ledger and build the pending list.

```
python tools/ledger.py pending <n>
```

`/step` is resumable. The ledger's `done` list is skipped and the step
continues, which is how a step survives the end of a conversation. Open the step
if it is not open:

```
python tools/ledger.py start <n> --targets <code> [<code> ...]
```

**Step 11 runs in three passes: `HIGH`, then `MEDIUM`, then `LOW`.** Landmarks
are written first because the thinner cells are written against them. Set the
pass before each one:

```
python tools/ledger.py pass HIGH
```

**Batch unit: one region per conversation at region and location scale.** That
is the largest unit that fits comfortably in context alongside its bundles.

## 3. Resolve one bundle per target.

```
python tools/resolve_deps.py --pattern <pattern-id> --target <code> [--var NAME=VALUE]
```

The bundle lands at `build/bundles/<pattern-id>-<target>.md` and already carries
the genre, the mechanics map, the one cell file and the config. Architect and
Engineer steps resolve a bundle too; they simply run it in the main session.

## 4. Dispatch.

**Architect and Engineer run in the main session.** They need the global view:
the roster, the graph and the container membership are decisions about a whole
region and cannot be made from a slice of it.

**Builder and Decorator run in a subagent, at most four at a time, one target
each.** Those phases write many files from a narrow slice, and the slice is the
point.

The subagent context contract is three inputs and one output, and it is not
negotiable:

1. **The pattern file** — `patterns/<scale>/<phase>.md`.
2. **The resolved bundle** — `build/bundles/<pattern-id>-<target>.md`.
3. **The current target file, including its stub.**

**Output:** the complete replacement content of the target file, and nothing
else. No commentary, no diff, no explanation of the choices.

**Prohibition: a subagent never reads the `setting/` tree directly.** If it
needs a fact that is not in its bundle, the dependency selector was wrong and
the pattern must change — which is `/pattern` and a booked step re-run, not a
workaround inside this call.

Give each subagent exactly one target. Four in flight is the ceiling: past that,
the returned files stop being written and validated as they arrive, and the
progress record starts lagging the work.

## 5. Write and validate each returned file.

Replace the target file with what came back. Then:

```
python tools/validate.py --scope <region-or-code>
```

A `REPORT (deferred: ...)` line is a check whose input has not been written yet
and is correct at this point in the build. An `ERROR` is not, and it is fixed
before the next target is dispatched rather than at the end of the step.

Where the step changed a `connections.md` or a container list, re-derive the
diagram layer before validating, or M11 and M13 both fail against a stale
`build/diagrams/`:

```
python tools/mermaid_gen.py
```

## 6. Record progress after every target, never only at the end.

```
python tools/ledger.py done <n> <code>
python tools/ledger.py built <code>        # after a Builder pass
python tools/ledger.py decorated <code>    # after a Decorator pass
```

`built` is the overwrite guard: `scaffold.py` refuses a target listed there, and
regeneration is then a booked step re-run passing `--rerun`, never a hand-patch.
`decorated` is what makes M25 apply to the file.

## 7. Close the step.

```
python tools/ledger.py complete <n>
python tools/validate.py
python -m unittest discover -s tests
```

`STATE.md` is regenerated by `ledger.py` and is never edited by hand.
